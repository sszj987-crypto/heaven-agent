# Heaven Agent 语音组件自动安装设计

## 背景与根因

macOS 语音安装当前依赖 `mlx-audio-plus==0.1.8`。该发行包错误地、无版本约束地声明了 `mlx-audio[all]`，导致 pip 在解析依赖冲突时遍历大量历史版本。旧版 `mlx-audio` 不提供 `all` extra，因此终端持续输出警告并长时间回溯，安装无法可靠完成。

## 产品设计

语音安装入口保留在“档案 → 语音音色”，不移动到设置页。页面只展示一条当前状态和一个主操作按钮：

- 未安装：显示“安装语音组件”。
- 安装中：显示当前阶段，按钮禁用。
- 已安装待重启：提示重启 Heaven Agent 生效。
- 已安装：允许上传或录制声音样本。
- 安装失败：显示脱敏失败摘要，并允许重试。

依赖清单、模型文件和 ffmpeg 的细分检查不在主界面展开，只作为后端诊断信息和失败原因使用。

## 技术设计

后端提供语音安装状态查询和显式安装接口。安装作为单例后台任务运行，前端轮询状态；同一时间只能存在一个安装任务。接口需要 `X-Heaven-Action: install-voice` 确认头，避免普通跨站请求触发大型依赖下载。

Bootstrap 继续作为命令行与界面的统一安装入口。macOS 安装将项目真正需要的运行依赖显式安装，再用 `--no-deps` 安装固定版本 `mlx-audio-plus`，绕过其错误的 `mlx-audio[all]` 元数据。安装命令关闭 pip 进度条并捕获冗长输出，只报告有限阶段和失败尾部。模型下载支持断点续传，并在结束时校验关键权重文件。

运行中的后端不会热加载新安装的大型模块。安装完成写入“待重启”状态；重启后由实际模块与模型探测决定是否变为“已安装”。

## 数据与 API

- `GET /system/voice-installation`：返回 `state`、`message`、`stage`、`restart_required` 和可选 `job_id`。
- `POST /system/voice-installation`：返回 `202 + job_id`；拒绝重复安装任务。
- 安装状态保存在 `data/system/voice-installation.json`，使用原子写入，不包含完整 pip 输出或用户数据。
- `GET /system/status` 继续提供整体语音能力，前端语音面板使用专用安装状态接口展示当前状态。

## 错误与恢复

安装失败不会破坏文字模式，也不会修改 Soul 档案。失败状态只保存命令阶段、退出码和经过长度限制的错误尾部。再次点击安装会复用 pip 缓存和模型断点文件继续执行。依赖安装成功但后端未重启时保持“已安装待重启”。

## 测试

- Bootstrap 单元测试覆盖 macOS 特殊安装顺序、安静输出、固定版本和模型完整性判断。
- 服务测试覆盖状态机、单任务限制、成功待重启与失败摘要。
- API 测试覆盖确认头、`202`、重复请求和类型化响应。
- 前端测试覆盖状态映射和安装请求确认头。
- 保留后端全量测试、前端测试、ESLint、TypeScript 和 production build 验证。
